# PaperTrail

Invoices and PDFs in, clean spreadsheet rows out, with every uncertain field flagged for a human instead of guessed.

> **Status: in the lab.** Not deployed yet. All numbers below come from synthetic test documents.

## What it does today

- Upload a PDF or image invoice after signing in with Google.
- The model reads the file directly and returns a Zod-validated invoice. Every field carries a value, a confidence (0–1) and the exact text it was read from.
- An answer that fails validation gets one repair retry, with the errors fed back. If it still fails, the document is marked for a person. Partial data is never returned.
- A review screen puts the document beside its fields and highlights the low-confidence ones. A person's correction is stored next to the model's value, never over it.
- Every model call is logged with its tokens, cost, latency and outcome.

**Not built yet:** escalation to the stronger model, CSV and XLSX export, and deployment.

**Stack:** Next.js (App Router), TypeScript, Tailwind · Vercel AI SDK with OpenAI (Responses API) · Zod · Supabase (Postgres, Storage, Auth) · Vitest.

## Results: which model to use

**How it's measured.** Ten synthetic invoices (11 files, one as both PDF and PNG). Each has ground truth copied by hand from its source document, never from model output. Before comparing, every field is normalised:

- dates → ISO, using the document's own date order;
- amounts → integer cents;
- text → case-folded, with whitespace collapsed.

Each field then scores as correct, wrong, missed or hallucinated.

- **Silent error:** wrong and *not* flagged, so nobody would see it. Keeping this at zero is the point of the product.
- **Caught error:** wrong, but below the confidence threshold, so a person reviews it.

**Decision: `gpt-6-luna` stays the primary model.** It has fewer silent errors and higher accuracy, and it's about 22× cheaper per document.

**Caveats:**

- These 10 documents are close to luna's ceiling. A harder 30-document set comes next.
- Luna's only error is reading `QA-2O61` (with a letter O) exactly as printed, where the ground truth expects the intended `QA-2061`. It was flagged every time.
- Most of sol's errors are an empty currency on invoices that print only `$`. That is arguably stricter than the ground truth, and it's an open rule.

## Run it locally

```bash
npm install
cp .env.example .env.local   # OpenAI and Supabase keys; apply supabase/migrations to your project
npm run dev                  # the app on http://localhost:3000
npm test                     # unit tests; they never call the model
npm run extract -- samples/synthetic-harbor-pine-inv-2041.pdf   # one extraction, about $0.0005
npm run eval -- --limit 0.10                                    # score against the ground truth; costs money
npm run eval:report          # regenerate the results table above from its run file
```

## Data

Synthetic documents only. Every file in `samples/` was generated for this project and says so on the page. No real invoices and no client or patient data, not even redacted.
