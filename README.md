# PaperTrail

Invoices and PDFs in, clean spreadsheet rows out, with every uncertain field flagged for a human instead of guessed.

> **Status: in the lab.** Not deployed yet. All numbers below come from synthetic test documents.

## What it does today

- Upload a PDF or image invoice after signing in with Google.
- The model reads the file directly and returns a Zod-validated invoice. Every field carries a value, a confidence (0–1) and the exact text it was read from.
- An answer that fails validation gets one repair retry, with the errors fed back. If it still fails, the document is marked for a person. Partial data is never returned.
- A review screen puts the document beside its fields and highlights the low-confidence ones. A person's correction is stored next to the model's value, never over it.
- Every model call is logged with its tokens, cost, latency and outcome.

**Not built yet:** escalation to the stronger model, CSV and XLSX export, and deployment.

**Stack:** Next.js (App Router), TypeScript, Tailwind · Vercel AI SDK with OpenAI (Responses API) · Zod · Supabase (Postgres, Storage, Auth) · Vitest.

## Results

**How it's measured.** Synthetic invoices, each with ground truth copied from its source document, never from model output. Before comparing, every field is normalised:

- dates → ISO, using the document's own date order;
- amounts → integer cents;
- text → case-folded, with whitespace collapsed.

Each field then scores as correct, wrong, missed or hallucinated.

- **Silent error:** wrong and *not* flagged, so nobody would see it. Keeping this at zero is the point of the product.
- **Caught error:** wrong, but below the confidence threshold, so a person reviews it.

**Decision: `gpt-6-luna` stays the primary model.** It has fewer silent errors and higher accuracy, and it's about 22× cheaper per document.

- These numbers were scored under the rules of 1 Nov. Most of sol's errors were an empty currency on invoices that print only `$`. The ground truth now accepts that (a `$`-only currency with a US address may be `USD` or empty), so on today's rules sol would score higher, but still below luna and still at 22× the cost.

### Baseline (30 documents, 2 Nov)

The ten original invoices plus 19 harder ones:
- three pages with 42 lines, and a row split across a page break;
- a credit note, two tax rates;
- German, French, Portuguese and Spanish;
- yen without decimals, `$` meaning MXN;
- a handwritten total, a rotated scan, a PDF whose second page is only an image;
- a PAID stamp, an FX reference amount;
- lines with no quantities, decimal quantities, shipping and a discount in the summary;
- the customer's name where the vendor's usually is.

See [`samples/README.md`](samples/README.md). This run is the baseline in [`evals/baseline.json`](evals/baseline.json).

**What the baseline shows:**

- **One silent error, and it's the important kind.** On the rotated low-resolution scan, luna read the invoice number `RO-60218` as `FO-60218` (once `FO-00218`) at 0.98–0.99 confidence, in all three runs. No threshold short of 1.0 would flag it. Confidence can't catch a confident misread, so that needs another safeguard.
- **The other error is caught.** On Quarry & Ash, luna reads the printed `QA-2O61` (letter O) where the ground truth expects the intended `QA-2061`, and flags it every time at 0.70–0.78.
- **Everything else was right in all 90 runs**: dates in four languages, credit-note negatives, decimal quantities, the image-only page, the handwriting, the summary charges and the customer-first header.

**Confidence threshold: 0.85 stays.** The rule, fixed before the sweep: fewest silent errors, then the fewest fields sent to review, and the current value stays on a tie. 0.80 and 0.85 tie on both counts. Thirty documents leave no held-out set, so this is tuned and reported on the same data. The value should be re-checked as the set grows.

## Run it locally

```bash
npm install
cp .env.example .env.local   # OpenAI and Supabase keys; apply supabase/migrations to your project
npm run dev                  # the app on http://localhost:3000
npm test                     # unit tests; they never call the model
npm run extract -- samples/synthetic-harbor-pine-inv-2041.pdf   # one extraction, about $0.0005
npm run eval -- --limit 0.10                                    # score against the ground truth; costs money
npm run eval:report          # regenerate the results table above from its run file
```

## Data

Synthetic documents only. Every file in `samples/` was generated for this project and says so on the page. No real invoices and no client or patient data, not even redacted.
